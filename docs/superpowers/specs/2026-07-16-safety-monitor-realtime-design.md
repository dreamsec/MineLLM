# 安全监测分站实时数据前端设计

## 目标

在现有“首页大屏”菜单下新增“安全监测”子菜单，展示分站
`24080000000043` 的实时传感器数据。首屏默认展示激光甲烷、粉尘和环境温度，
并允许用户切换为全部传感器。

## 页面结构

- 路由：`/dashboard/safety-monitor`
- 菜单位置：与提升机、压风机、通风机、排水泵、皮带机同级
- 顶部信息：分站名称、分站编码、返回数量、整组最新监测时间
- 操作区：推荐类型/全部数据切换、手动刷新、自动刷新状态
- 内容区：按 `sensor_type` 分组，每个传感器以独立卡片展示
- 状态区：首次加载、刷新中、接口错误、无传感器、无实时记录

页面沿用现有大屏的深色监控风格和已有背景素材，但使用更适合扫描实时数据的
分组网格，不引入新的图片或第三方依赖。

## 数据与接口

新增安全监测 API 模块，请求：

```http
GET /api/v1/safety-monitor/stations/24080000000043/realtime
```

默认请求参数：

```text
types=激光甲烷,粉尘,环境温度
```

请求继续复用项目的 `request` 封装，由现有拦截器自动携带 Bearer Token。
前端不额外判断 `sensor:query`，权限不足时展示后端返回的错误。

切换“全部数据”时不传 `types`。切回“推荐类型”时恢复三个默认类型。新请求发起前
取消尚未完成的旧请求，避免慢响应覆盖新数据。

## 展示规则

- `value === null` 或 `value === undefined` 显示 `--`
- 数值 `0` 必须正常显示
- 单位与数值分开展示，避免空值被拼成 `--℃`
- `sensor_type` 为空时归入“未知类型”
- `sensor_name` 为空时回退到 `sensor_code`
- `latest_time` 或 `monitor_time` 为空时显示“暂无实时记录”
- `status_code` 只展示原始值，不转换为正常、故障或报警
- 类型使用稳定的颜色标识：激光甲烷为青色、粉尘为黄色、环境温度为红色，
  其他类型使用中性蓝色

## 刷新策略

- 页面首次进入立即请求
- 每 30 秒自动刷新
- 页面隐藏时停止定时器并取消进行中的请求
- 页面恢复可见时立即刷新并重新启动定时器
- 组件卸载时移除监听、停止定时器并取消请求
- 手动刷新复用相同请求逻辑

## 错误处理

- `code !== 1` 时保留当前页面框架并展示后端 `message`
- HTTP 或网络错误展示错误对象中的消息，无法提取时显示通用错误文案
- 刷新失败时不清空上一次成功数据，顶部标记本次刷新失败
- 首次请求失败时展示完整错误状态和“重新加载”按钮

## 测试与验收

纯数据逻辑通过 Node 断言脚本覆盖：

- 类型参数去空格、去重和空列表处理
- 传感器按类型分组及未知类型回退
- `0`、空值和单位的格式化
- 日期时间格式化及无效时间回退
- 类型颜色标识选择

完成后运行安全监测测试、项目类型检查和生产构建。开发过程不执行 Git 提交。
